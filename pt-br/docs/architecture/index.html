Direção de arquitetura

Pacotes modulares, limites explícitos do runtime, contratos compartilhados.

Revisado em novembro de 2026 · Repositório de código ↗

Pacotes modulares#

Os pacotes devem ter uma responsabilidade compreensível, declarar as capacidades de runtime que suportam e continuar úteis sem módulos não relacionados.

Contratos compartilhados#

Os contratos compartilhados incluem erros tipados, cancelamento, prazos, ciclo de vida de recursos, validação de configuração, ganchos de log e documentação de efeitos colaterais. Os contratos compartilhados devem reduzir a fragmentação sem dependências circulares ou impostas.

Limites do runtime#

O Node.js é o alvo inicial. As APIs devem explicitar suposições sobre o runtime e isolar comportamentos específicos de cada ambiente atrás de adaptadores quando for útil. Capacidades não suportadas devem falhar de forma clara.

Segurança de recursos#

Pacotes de rede e de streams devem definir tempos limite, tamanhos máximos, limites de concorrência, contrapressão, cancelamento e limpeza. Os padrões devem ser conservadores e configuráveis.

Compatibilidade respaldada por evidências#

Antes das versões estáveis, o projeto deve documentar as versões do Node.js suportadas, os formatos de módulo, o suporte a TypeScript, a política de versionamento semântico, os prazos de descontinuação e as expectativas de interoperabilidade. Afirmações de compatibilidade e desempenho precisam de testes reproduzíveis e de uma metodologia de benchmark.

Projeto independente. O Ametherian não é afiliado nem endossado pelo Node.js, pela OpenJS Foundation, pelo Axios, pelo Undici ou por qualquer outro projeto mencionado. Node.js é uma marca registrada da OpenJS Foundation.
