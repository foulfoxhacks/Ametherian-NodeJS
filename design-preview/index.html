Documentation / Architecture

Architecture direction

Ametherian is intended to use a modular package architecture. Each package should have one understandable responsibility and declare its runtime requirements.

Shared contracts

Consistent errors, cancellation, deadlines, resource lifecycle, and configuration validation.

import { createClient } from '@foulfoxhacks/ametherian-http';

// Illustrative proposal — not a released API
const client = createClient({
  timeout: 5_000,
  maxResponseBytes: 2_000_000
});
Examples are illustrative. Package names and APIs remain proposed until implemented and released.

BUILT ON PRINCIPLES

Serious about the
details that matter.

01

Security is engineering

Threat models, conservative limits, dependency review, and tested mitigations — not marketing promises.

02

Small packages, shared standards

Install only what you need while benefiting from coherent contracts and documentation.

03

Evidence over claims

Compatibility, performance, and security claims should be backed by reproducible evidence.
