Contributing

How to give feedback on the direction and architecture.

Reviewed November 2026 · Source repository ↗

Early feedback on scope, package boundaries, security requirements, runtime compatibility, and developer experience is welcome.

Giving feedback#

Open an issue to discuss proposals, architecture decisions, or documentation gaps. Keep discussions focused on the technical direction and evidence.

Pull requests#

Pull requests should be small, focused, and accompanied by a clear description of the problem and the proposed solution. Documentation and tests are part of the change.

Security-sensitive changes#

Do not post exploit details publicly. Follow the security policy for vulnerability reports and security-sensitive fixes.
