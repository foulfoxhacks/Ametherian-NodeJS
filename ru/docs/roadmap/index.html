Roadmap

Research, specifications, implementation, and release readiness.

Reviewed November 2026 · Source repository ↗

The roadmap is staged and deliberately avoids dates until scope, ownership, and capacity are established.

Research and project foundation#

Done. Establish the repository, documentation, and initial research areas. Review existing libraries and identify where consistent contracts would help.

Specifications and threat models#

Done for the preview packages. Write explicit specifications. Define threat models, resource bounds, failure modes, and support matrices.

Implementation and verification#

In progress. Ten packages are implemented with tests, fuzzing and a vulnerability model. Independent security review is still required before any package can be described as stable.

Release readiness#

Not started. A package is not stable or production-ready until its API, support matrix, documentation, tests, security review, release process, and maintenance ownership are explicit. A license must be chosen first.
