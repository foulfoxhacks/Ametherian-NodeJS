How to read the documentation#

  • Planning is not implementation. A described capability, package name, or security control is a direction until source, tests, documentation, and a release exist.
  • Claims need evidence. Compatibility, performance, reliability, and security statements must be reproducible or explicitly labeled as goals.
  • Dates are not promises. The roadmap is staged. Release commitments are not published until scope, ownership, and capacity are established.
  • Third-party names identify context. Axios, Undici, Node.js, and OpenJS are referenced to describe the ecosystem and constraints, not to imply affiliation or endorsement.
