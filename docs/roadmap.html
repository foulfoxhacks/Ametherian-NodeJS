Roadmap

Research, specifications, implementation, and release readiness.

Reviewed November 2026 · Source repository ↗

The roadmap is staged and deliberately avoids dates until scope, ownership, and capacity are established.

Research and project foundation#

Establish the repository, documentation, and initial research areas. Review existing libraries and identify where consistent contracts would help.

Specifications and threat models#

Write explicit specifications for candidate packages. Define threat models, resource bounds, failure modes, and support matrices.

Implementation and verification#

Implement packages against the specifications. Require tests, fuzzing where appropriate, and security review before a package can be described as stable.

Release readiness#

A package is not stable or production-ready until its API, support matrix, documentation, tests, security review, release process, and maintenance ownership are explicit.
