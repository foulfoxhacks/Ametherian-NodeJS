Architecture direction

Modular packages, explicit runtime boundaries, shared contracts.

Reviewed November 2026 · Source repository ↗

Modular packages#

Packages should have one understandable responsibility, declare supported runtime capabilities, and remain useful without unrelated modules.

Shared contracts#

Candidate shared contracts include typed errors, cancellation, deadlines, resource lifecycle, configuration validation, logging hooks, and documentation of side effects. Shared contracts should reduce fragmentation without circular dependencies or forced dependencies.

Runtime boundaries#

Node.js is the initial target. APIs should make runtime assumptions explicit and isolate environment-specific behavior behind adapters where useful. Unsupported capabilities should fail clearly.

Resource safety#

Network and stream-oriented packages should define timeouts, maximum sizes, concurrency bounds, backpressure, cancellation, and cleanup. Defaults should be conservative and configurable.

Evidence-backed compatibility#

Before stable releases, the project should document supported Node.js versions, module formats, TypeScript support, semantic versioning policy, deprecation windows, and interoperability expectations. Compatibility and performance claims need reproducible tests and benchmark methodology.
