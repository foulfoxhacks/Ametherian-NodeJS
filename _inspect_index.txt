<section class="intro-section">
<div class="content-width intro-grid">
<p class="section-label">The idea</p>
<div>
<h2>One ecosystem. Independent tools.</h2>
<p>Node.js developers rely on a broad mix of packages for networking, data, application infrastructure, security, and everyday development. Ametherian aims to bring a consistent engineering philosophy to that landscape without turning every capability into one large dependency.</p>
<p>Each future package should have a clear purpose, documented behavior, explicit limits, and the freedom to be adopted on its own.</p>
</div>
</div>
</section>

<section class="code-section">
<div class="content-width code-grid">
<div>
<p class="section-label">Engineering philosophy</p>
<h2>Familiar Node.js.<br>Better-defined building blocks.</h2>
<p>Ametherian is Node.js-first. Its direction is grounded in the runtime's established APIs and ecosystem rather than inventing a parallel way to write JavaScript.</p>
<a class="plain-link" href="/docs/architecture.html">Read the architecture direction →</a>
</div>
<div class="code-panel">
<div class="code-bar">
<span>node:http · native Node.js example</span>
<span>JavaScript</span>
</div>
<pre>
<code>
<span class="code-muted">// A familiar foundation</span>
<span class="code-key">import</span> { createServer } <span class="code-key">from</span> <span class="code-string">'node:http'</span>;

<span class="code-key">const</span> server = createServer((request, response) =&gt; {
  response.writeHead(<span class="code-number">200</span>, {
    <span class="code-string">'content-type'</span>: <span class="code-string">'text/plain'</span>
  });
  response.end(<span class="code-string">'Hello from Node.js\n'</span>);
});

server.listen(<span class="code-number">3000</span>);</code>
</pre>
<p class="code-note">Native Node.js example — not an Ametherian package API.</p>
</div>

<section class="principles-section">
<div class="content-width principles-grid">
<div>
<p class="section-label">Project principles</p>
<h2>Clarity is part of the contract.</h2>
</div>
<ul>
<li>Small packages with explicit responsibilities.</li>
<li>Documented runtime support and compatibility.</li>
<li>Conservative resource limits and visible failure behavior.</li>
<li>Security claims supported by tests and review.</li>
<li>Interoperability with established libraries where it makes sense.</li>
</ul>
</div>
