<h1>Security policy</h1>
<h2>Current status</h2>
<p>Ametherian is a planning repository. There are no released Ametherian packages or audited security guarantees represented here.</p>
<h2>Reporting a vulnerability</h2>
<p>Until a private reporting channel is configured, do not send sensitive vulnerability details through public Issues or Discussions. Contact the maintainers through a verified private channel listed on the repository's GitHub Security tab once it is enabled.</p>
<p>Do not include live credentials, personal data, or data belonging to third parties in a report.</p>
<h2>Intended security process</h2>
<p>For future implementation repositories, the project intends to establish:</p>
<ul>
<li>A supported-version policy and security contact</li>
<li>Private vulnerability reporting and coordinated disclosure</li>
<li>Severity triage based on impact, exploitability, affected configurations, and known exploitation</li>
<li>Reproducible regression tests for confirmed vulnerabilities</li>
<li>Security advisories and patched release notes</li>
<li>Dependency, secret, static-analysis, and supply-chain checks</li>
<li>A documented emergency release and package-deprecation process</li>
</ul>
<h2>Security claims</h2>
<p>A security feature is not considered complete merely because it appears in a roadmap or configuration example. It must have a defined threat model, implementation, tests, documentation, and review. Independent audits must be described with their actual scope and date.</p>
