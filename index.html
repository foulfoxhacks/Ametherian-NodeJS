One ecosystem. Many focused tools.

The idea is not to turn every utility into one giant dependency. Ametherian is intended to grow through independently useful packages that share conventions for configuration, errors, lifecycle, compatibility, and security.

Why Ametherian?

Applications rely on a broad collection of libraries. Each package brings its own configuration model, lifecycle, errors, and security assumptions. Ametherian wants to explore a more coherent set of building blocks without removing the choice and specialization that make the JavaScript ecosystem useful.

The first research area compares Axios-style HTTP ergonomics with Undici-style transport architecture. The wider project reaches into common and specialist developer needs, with package scope determined by real use cases, maintainability, and the ability to test the result.

Security is part of the design

Security should not be a badge or an afterthought. Future packages are expected to define trust boundaries, limit resource consumption, handle credentials carefully, track relevant vulnerability research, and include regression tests for confirmed weaknesses. The project will distinguish proposed controls from implemented and independently reviewed controls.
