Independent Node.js Ecosystem

A new kind of Node library ecosystem.

Ametherian is a family of modular JavaScript and TypeScript libraries under the @foulfoxhacks npm scope. Its packages exist as tested previews: focused packages, shared contracts, and security considered from the first design decision.

Overview

One ecosystem. Independently adoptable tools.

Node.js developers assemble networking, validation, caching, concurrency, observability, and application infrastructure from many packages. Ametherian investigates where consistent contracts and well-defined package boundaries could make that work easier to understand and maintain.

Each package has a clear purpose, documented behavior, explicit limits, and the freedom to be adopted on its own. The ambition is broader than replacing a single HTTP client.

Architecture

Built on Node.js primitives.

Ametherian builds on the runtime’s established APIs rather than inventing a parallel way to write JavaScript. Compatibility and performance claims will need reproducible evidence before they are published.

Read the architecture direction →

import { createServer } from 'node:http';

const server = createServer((request, response) => {
  response.writeHead(200, { 'content-type': 'text/plain' });
  response.end('Hello from Node.js\n');
});

server.listen(3000, () => {
  console.log('Listening on http://localhost:3000');

Guiding Principles

Development guidelines.

These principles are requirements for every package; tests, threat models and review check them. They apply to package boundaries, documentation, tests, and review.

Focused packages

A package should have one understandable responsibility and remain useful without unrelated modules.

Explicit behavior

Runtime requirements, side effects, limits, failure modes, and data handling should be documented rather than hidden.

Interoperability

Learn from established libraries, interoperate where useful, and avoid unnecessary reinvention.

Evidence over claims

Compatibility, performance, security, and reliability statements need reproducible tests or a clear label as goals.

Security by design

Threat models, bounded resources, and safe defaults belong in the design, not in a later checklist.

Human-reviewed change

Security-sensitive fixes and public claims require review by people accountable for the result.

FAQ

About the project.

Direct answers about status, affiliation, runtime, licensing, and contribution.

Is Ametherian released?

Not to npm yet. The preview packages are public in the repository with tests, and every green build is published as a numbered preview on GitHub Releases. Publishing to npm waits for an agreed release process.

Is Ametherian affiliated with Node.js or the OpenJS Foundation?

No. Ametherian is an independent project from FoulFoxHacks. It is not affiliated with, endorsed by, or an official continuation of Node.js, the OpenJS Foundation, Axios, Undici, or any other referenced project. Node.js is a trademark of the OpenJS Foundation.

Is Ametherian production-ready or audited?

No. The packages exist as tested previews, but none is published to npm and no independent security audit has been performed. The security approach and the vulnerability model describe how the code is threat-modelled and tested; they are not a guarantee that it is secure.

What runtime does Ametherian target?

Node.js 22, 24 and 26, each at its latest security release. Packages are ES modules with TypeScript declarations. Node.js 20 is not supported: it reached end of life in April 2026.

What license will the project use?

The Apache License 2.0. It is a permissive license with an explicit patent grant. The full text is in the licensing status and in every package.

Can I contribute?

Early feedback on scope, package boundaries, security requirements, runtime compatibility, and developer experience is welcome. The contributing guide explains expectations. Security-sensitive details must not be posted publicly; follow the security policy.

Is there a release timeline?

There are no dates. Every build of the main branch that passes CI is published as a numbered preview build on GitHub Releases, listed in the changelog. Publishing to npm waits for an agreed release process.

Does Ametherian replace Axios or Undici?

No. The Ametherian HTTP client and fetch() are its own code, checked against every published Axios and Undici advisory. It is not a drop-in replacement and makes no compatibility or performance claim without reproducible evidence.
